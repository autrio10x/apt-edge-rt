Keystone

Public apt archive. Install the daemon on an ABOX or other Ubuntu host. Source stays in the private keystone repo.

Current package

keystone 0.1.3 · amd64 · suite stable

Install

  1. Add the archive (once per machine). Ubuntu already has an OpenStack package named keystone. Pin this archive so apt does not pick that one, and so upgrades are not stuck on an old Autrio version. 
    sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://autrio10x.github.io/apt-edge-rt/keystone.gpg \
  | sudo tee /etc/apt/keyrings/keystone.gpg >/dev/null
echo "deb [signed-by=/etc/apt/keyrings/keystone.gpg] https://autrio10x.github.io/apt-edge-rt stable main" \
  | sudo tee /etc/apt/sources.list.d/keystone.list
sudo tee /etc/apt/preferences.d/keystone-autrio >/dev/null <<'EOF'
Package: keystone
Pin: origin autrio10x.github.io
Pin-Priority: 1001
EOF
  2. Refresh the index, then install. On an ABOX-5210G with a TPM the vault is tpm2. If that TPM device is missing, install fails. 
    sudo apt update
sudo apt install keystone
  3. Fill identity, then start. Leave this file empty and the service will restart in a loop. 
    sudo nano /etc/keystone/keystone.toml
sudo systemctl enable --now keystone
keystone status

Identity file

Ops supplies these four values. They are not in the package.

autrio_url = "…"
tenant_key = "…"
serial = "…"
birth_secret = "…"

Check

keystone --version
keystone status

keystone status should show layout: package, running: yes, and on an ABOX keystore: tpm2.

Upgrade

sudo apt update
sudo apt install keystone

The identity file is kept. If a pin file still says Pin: version 0.1.2, replace it with the origin pin above, then run these two commands again.
